# Вайрфрейм-прототип «серыми блоками»

Эталон формата: блочный прототип «серыми блоками» (см. пример в assets/build.py).
Готовые файлы-образцы лежат в `assets/` этого скилла: `build.py` (полный
генератор БРЕНД — брать за основу), `wire.css`, `comments.js`, `server.js`.

## Зачем такой формат

Клиент видит СТРУКТУРУ и ТЕКСТЫ без отвлечения на дизайн; каждый блок подписан
и прокомментирован; кликабельность честная (все переходы работают). Дёшево
править до вёрстки. Дизайн потом делается через Claude Design поверх
согласованной структуры.

## Визуальные конвенции (обязательные)

- Белый фон; каждый смысловой блок = `<section>` — светло-серая карточка
  (#fafafa, рамка #ddd, radius 14px).
- У секции сверху слева **пилюля-лейбл**: `N · НАЗВАНИЕ БЛОКА` (uppercase,
  10-11px, серый) — нумерация сквозная по странице, чтобы обсуждать «блок 5».
- Внизу секции **аннотация-курсив** `→ зачем этот блок / откуда контент /
  что уточнить у клиента` (12.5px, #9a9a9a). Это язык общения с клиентом.
- **Фото-плейсхолдеры**: штрихованный фон (repeating-linear-gradient 45°),
  пунктирная рамка, внутри серым текстом ЧТО за фото должно быть
  («Фото: открытый бокс, бежево-золотая гамма»).
- Реальные тексты, а не lorem: заголовки, офферы, CTA пишутся начисто.
  Цены/цифры, которых нет, помечать «заглушка» или «N» прямо в тексте.
- Кнопки: чёрная заливка (primary) / чёрная рамка (ghost). Чипсы-пилюли для
  тегов и маркеров доверия.
- **Кликабельные карточки** (ведут на другие страницы) — класс `.hot`:
  рамка 2px чёрная, тень, hover-подъём, бейдж сверху «КЛИК · СТРАНИЦА …»,
  внизу жирное «Смотреть → ». Всё остальное серое — они бросаются в глаза.
- Шапка: логотип + 5-6 основных пунктов + CTA; остальное в бургер
  (чекбокс-хак, без JS); ≤1100px всё меню в бургере. Футер простой.

## Структурные принципы

- Страницы направлений/услуг — по прогревающей формуле, а НЕ витриной:
  1 hero-оффер под роль покупателя (+чипсы доверия, 2 CTA) → 2 готовые
  продукты/наборы (акцентные .hot карточки СРАЗУ под hero) → 3 боли
  «Знакомо?» (4 карточки-цитаты) → 4 переворот-решение (позиционирование) →
  5 анатомия продукта → 6 сценарии/задачи → 7 выгоды языком KPI этой роли →
  8 мини-кейс → 9 процесс кратко → 10 FAQ под роль → 11 лид-магнит →
  12 финальная форма.
- Мини-страница продукта/набора: заголовок по центру (кикер → H1 → смысл →
  чипсы цена/тираж/срок → CTA-якорь) → фото с **выносками** (annwrap: слева и
  справа от фото названия предметов + смыслы) → «Закажите…» (галочки выгод +
  плашка условий + форма) → похожие продукты (перелинковка).
- Всё кликабельное реально линкуется; каталог/витрины ведут на мини-страницы.

## Технология

1. Один `build.py`: словарь страниц + хелперы `sec/ph/card/hotcard/pain/
   metric/lead_form`, данные продуктов в dict `SETS`, генерация мини-страниц
   циклом. `python3 build.py` → `dist/`. Никаких фреймворков.
2. Деплой: `scp dist/* root@<IP-сервера>:/var/www/<slug>/`
   (ключ `~/.ssh/id_server`). Nginx: в
   `/etc/nginx/sites-available/default`, блок `listen 80 default_server`,
   добавить location по образцу cityblank/your-slug:
   `location /<slug>/ { alias /var/www/<slug>/; index index.html; }` →
   `nginx -t && systemctl reload nginx`.
3. Проверка: curl всех страниц на 200 + браузер-превью (клики, бургер,
   мобилка 375px). После правки nginx — curl https://example.ru не задет.

## Комментарии клиента (по желанию проекта)

Клиент оставляет правки прямо в прототипе, они падают на сервер:
- фронт `comments.js` (кнопка «💬 Комментировать» на каждой секции по
  `.sec-label`, плавающая «Комментарий к странице», стикеры жёлтые);
- бэк `server.js` — Node без зависимостей, порт 127.0.0.1:3777+, PM2
  (`pm2 start server.js --name <slug>-comments && pm2 save`), хранение
  `comments.json` рядом (поля id/ts/page/section/text);
- nginx: `location /<slug>/api/ { proxy_pass http://127.0.0.1:<port>/; }`;
- читать правки: `curl -s http://<IP-сервера>/<slug>/api/comments` —
  сгруппировать по page+section и обсудить с Дмитрием.
- БРЕНД использует порт 3777 — для нового проекта взять СВОБОДНЫЙ порт.
