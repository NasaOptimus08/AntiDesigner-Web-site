# Вайрфрейм-прототип «серыми блоками» с комментариями

**Обновлено: 25.08.2026**

Прототип, который клиент видит и правит ещё до дизайна. Клиент видит СТРУКТУРУ и
ТЕКСТЫ, не отвлекаясь на оформление, каждый блок подписан, и по каждому можно
оставить комментарий прямо на странице. Дёшево править до вёрстки. Дизайн потом
делается поверх согласованной структуры.

## Визуальные конвенции

- Белый фон; каждый смысловой блок это `<section>` — светло-серая карточка
  (#fafafa, рамка #ddd, скругление 14px).
- Сверху слева у секции пилюля-лейбл: `N · НАЗВАНИЕ БЛОКА` (капсом, 10–11px,
  серый). Нумерация сквозная по странице, чтобы обсуждать «блок 5».
- Внизу секции аннотация курсивом: `→ зачем этот блок / откуда контент / что
  уточнить у клиента` (12.5px, серый). Это язык общения с клиентом.
- Фото-плейсхолдеры: штрихованный фон (repeating-linear-gradient 45°),
  пунктирная рамка, внутри серым текстом что за фото должно быть («Фото:
  интерьер, вечерний свет»).
- Реальные тексты, а не lorem: заголовки, офферы, кнопки пишутся начисто.
  Цены и цифры, которых нет, помечать «заглушка» или «N» прямо в тексте.
- Кнопки: чёрная заливка (основная) или чёрная рамка (второстепенная).
- Кликабельные карточки (ведут на другие страницы): рамка 2px чёрная, тень,
  подъём на наведении, бейдж «КЛИК · СТРАНИЦА …», внизу жирное «Смотреть →».
  Всё остальное серое, они бросаются в глаза.
- Шапка: логотип + 5–6 пунктов + кнопка; остальное в бургер. Футер простой.

## Структура страниц (по прогревающей формуле, не витриной)

Страница услуги или сегмента:
1. Hero-оффер под конкретную роль покупателя (+ чипсы доверия, 2 кнопки)
2. Готовые продукты или пакеты (акцентные кликабельные карточки сразу под hero)
3. Боли «Знакомо?» (4 карточки-цитаты)
4. Переворот-решение (позиционирование)
5. Анатомия продукта
6. Сценарии и задачи
7. Выгоды языком результата этой роли
8. Мини-кейс
9. Процесс кратко
10. FAQ под роль
11. Лид-магнит
12. Финальная форма

Всё кликабельное реально линкуется; витрины ведут на мини-страницы продуктов.

## Технология

Один генератор на Python (`build.py`): словарь страниц + функции-хелперы для
секций, карточек, форм. `python3 build.py` собирает готовые HTML в папку. Без
фреймворков. Дальше заливаете папку на свой сервер (или открываете локально) и
показываете клиенту ссылку.

## Комментарии клиента на прототипе

Клиент оставляет правки прямо на прототипе, они сохраняются на сервере:

- **Фронт `comments.js`** (в комплекте): кнопка «💬 Комментировать» на каждой
  секции по классу `.sec-label`, плюс плавающая «Комментарий к странице»,
  стикеры-заметки. Подключается одной строкой `<script src="comments.js">`.
- **Бэк `server.js`** (в комплекте): Node без зависимостей, слушает localhost,
  наружу выводится через ваш веб-сервер. Хранит правки в `comments.json` рядом
  (поля id, время, страница, секция, текст). Запуск: `node server.js` (или под
  менеджером процессов, чтобы работал постоянно).
- Веб-сервер проксирует `/api/` вашего прототипа на порт этого `server.js`.
- Читать правки: запросить `.../api/comments` — сгруппировать по странице и
  секции и пройтись по ним.

## Как это связано с разбором ниши

Сначала вы просите Claude Code разобрать нишу клиента (аудитория, конкуренты,
что чинить), затем на основе этого разбора собираете прототип по этому скиллу.
Клиент кликает, оставляет комментарии или надиктовывает правки, вы дорабатываете.

## Чек-лист сдачи

- [ ] Все страницы открываются, карточки-ссылки ведут куда надо
- [ ] Нумерация блоков сквозная, у каждого блока аннотация
- [ ] Заглушки помечены («цена-заглушка», «N»)
- [ ] Мобилка: меню в бургере, колонки складываются в одну
- [ ] Список «что уточнить у клиента» собран
