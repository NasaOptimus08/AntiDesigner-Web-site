# Скорость загрузки сайта

**Обновлено: 30.07.2026**

Проверено на реальных проектах — **100/100/100/100
на десктопе и мобиле** (у оригиналов на Тильде перф был ~51), клиентский сайт **56 → 95**,
личный кабинет — вес картинок **148 МБ → 37 МБ**.

## Порядок работы (не нарушать)

1. **Сначала замерить, потом чинить.** Без замера правки делаются вслепую.
2. Смотреть не на общий балл, а на **что именно тормозит**: LCP (когда появилась
   главная картинка/заголовок), CLS (прыгает ли вёрстка), TBF/TBT (сколько висит JS).
3. Чинить по убыванию веса: **картинки → видео → сторонние скрипты → шрифты → CSS/JS**.
4. После каждой пачки правок — замер заново. Иначе не понять, что помогло.

Замер без браузера (можно гнать прямо из терминала):
```
curl -s "https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=https://САЙТ&strategy=mobile" \
  | python3 -c "import json,sys; d=json.load(sys.stdin)['lighthouseResult']; \
print('perf', d['categories']['performance']['score']*100); \
[print(k, v['displayValue']) for k,v in d['audits'].items() if k in ('largest-contentful-paint','cumulative-layout-shift','total-blocking-time','speed-index')]"
```
Мобильная стратегия строже десктопной — ориентироваться на неё.

## 1. Картинки (даёт больше всего)

**Правило: ни одна картинка не лежит несжатой.** Это корень 80% медленных сайтов.

- Всё, что можно, → **WebP**. На этом Маке ffmpeg и sips WebP не умеют, гнать через
  Python Pillow (`im.save(out, 'WEBP', quality=75, method=6)`), качество 70–78.
- **Ещё легче — AVIF** (−20–40% к WebP при том же качестве). Отдавать через `<picture>`
  с фоллбэком, браузер сам выберет: `avifenc in.png -q 60 out.avif` (или
  `ffmpeg -i in.jpg -c:v libaom-av1 -crf 30 -still-picture 1 out.avif`).
  ```html
  <picture>
    <source srcset="hero.avif" type="image/avif">
    <source srcset="hero.webp" type="image/webp">
    <img src="hero.jpg" width="1600" height="900" fetchpriority="high" alt="…">
  </picture>
  ```
- Размер под реальное место на странице: фон/герой ≤1920px по ширине, карточки ≤800,
  аватары ≤512. Отдавать 3000px картинку в блок 400px — самая частая ошибка.
- **SVG прогонять через svgo** (в проекте был кейс 417 КБ → 186 КБ).
- Фото ниже первого экрана — `loading="lazy"`; первые 2–3 — `fetchpriority="high"`.
- У `<img>` всегда указывать ширину/высоту (или aspect-ratio) — иначе прыгает вёрстка
  и падает CLS.

Ориентир: страница целиком (без видео) должна укладываться в **1–1.5 МБ**.

## 2. Видео

- Перед заливкой сжимать всегда — см. скилл `video-compress` (H.264 1080p CRF 22,
  faststart). Фоновые лупы без звука — CRF 27.
- **Видео никогда не грузится вместе со страницей**: `preload="none"`, реальный `src`
  подставлять лениво.
- **Постер — это LCP.** Ставить настоящий `<img fetchpriority="high">` с WebP-постером,
  а не `poster=""` у video. Так первый экран рисуется мгновенно, пока видео ещё едет.
- Ролики с YouTube/Kinescope — **фасад по клику** (картинка + кнопка play, iframe
  вставляется только после клика). Один такой iframe в вёрстке тянет 1–2 МБ чужого JS.
- Автозапуск фонового видео — только на десктопе (`min-width:900px`) и не при
  `navigator.connection.saveData`.

⚠️ **Грабля Chrome**: `play()` из скрипта отклоняется автоплей-политикой, если вызван
до готовности данных. Для геро-видео надёжнее нативные атрибуты прямо в HTML
(`autoplay muted playsinline preload="metadata"`) — браузер сам разрулит.

## 2б. Видео на сайт: форматы нового поколения + автоплей + HDR

То же, что WebP/AVIF сделали для картинок, для видео делает **WebM (AV1/VP9)**: тот же
кадр весит в 1.5–3× меньше H.264. Отдаём несколько `<source>` — браузер берёт первый,
который умеет; mp4/H.264 держим последним для совместимости (iOS Safari, старьё).
Кодирование команд — в скилле `video-compress` (раздел «Веб-видео»).

**Фоновое / герой-видео с автоплеем (SDR, базовый рецепт):**
```html
<video autoplay muted loop playsinline preload="metadata"
       poster="hero-poster.webp"
       style="width:100%;height:100%;object-fit:cover">
  <source src="hero.webm" type="video/webm">   <!-- AV1/VP9 — лёгкий -->
  <source src="hero.mp4"  type="video/mp4">    <!-- H.264 — iOS/совместимость -->
</video>
```
- **`muted` + `playsinline` — обязательны**, иначе iOS не запустит автоплей (или откроет
  фуллскрин). `autoplay` без `muted` не сработает нигде. `loop` — если фон бесшовный.
- **`poster` — WebP-картинка первого кадра** = мгновенный первый экран (LCP), пока видео
  едет. Не оставлять чёрный `poster` пустым.
- Экономия трафика тем, у кого включён режим экономии:
  ```js
  const v = document.querySelector('video[autoplay]');
  if (navigator.connection?.saveData) { v.removeAttribute('autoplay'); v.load(); }
  else v.play().catch(()=>{}); // iOS Low Power Mode: останется постер до тапа — это ок
  ```
- Фоновые (декоративные) видео — только на десктопе (`@media (min-width:900px)`), на
  мобиле отдавать постер: экономит трафик и батарею, мобилка всё равно почти не покажет.

**HDR-видео с SDR-фоллбэком** (наш выбор: HDR только на HDR-экранах, остальным чистый SDR —
никаких «поплывших» цветов). Порядок `<source>`: сперва HDR под `media`-условие, потом SDR:
```html
<video autoplay muted loop playsinline poster="hero-poster.webp" id="hero"
       style="width:100%;height:100%;object-fit:cover">
  <source src="hero-hdr.webm" type="video/webm"            media="(dynamic-range: high)"><!-- AV1 HDR10 — Chrome/Android -->
  <source src="hero-hdr.mp4"  type='video/mp4; codecs=hvc1' media="(dynamic-range: high)"><!-- HEVC HDR — Safari -->
  <source src="hero-sdr.webm" type="video/webm">                                          <!-- SDR AV1/VP9 -->
  <source src="hero-sdr.mp4"  type="video/mp4">                                           <!-- SDR H.264 — дефолт -->
</video>
```
⚠️ Атрибут `media` на `<source>` внутри `<video>` учитывают не все браузеры при выборе.
Для надёжности продублировать JS-детектом и подставить HDR-src руками:
```js
const hdr = matchMedia('(dynamic-range: high)').matches
         || matchMedia('(video-dynamic-range: high)').matches;
if (hdr) { /* переставить/выбрать HDR <source> и v.load() */ }
```
- HDR виден **только на HDR-дисплее** (телефоны последних лет, часть маков) и весит больше,
  поэтому SDR-версия обязательна и остаётся дефолтом. **SDR делаем не «просто в 8 бит», а
  тон-маппингом** из HDR-исходника (иначе на SDR-экране пересвет/блёклость) — команда в
  `video-compress`.
- Хостинг: HDR-ролики тяжёлые — если это не короткий фон, лучше отдавать через видеохостинг
  (Kinescope) или CDN, а не со своего сервера (см. раздел 7).

## 3. Ленивая загрузка всего тяжёлого

Карты (MapLibre, Яндекс.Карты), чаты, счётчики, тяжёлые библиотеки — **не в `<head>`**,
а подгружать при подходе к блоку через IntersectionObserver.

⚠️ **Чистый IntersectionObserver ненадёжен** (в части браузеров и в headless-превью может
вообще не сработать). Всегда делать фоллбэк по первому взаимодействию:
```js
function loadAll(){ document.querySelectorAll('[data-src]').forEach(el=>{
  if(el.dataset.src){ el.src = el.dataset.src; delete el.dataset.src; } }); }
const io = new IntersectionObserver(es=>es.forEach(e=>{ if(e.isIntersecting){ /* грузим */ }}));
document.querySelectorAll('[data-src]').forEach(el=>io.observe(el));
['scroll','touchstart','click'].forEach(ev=>addEventListener(ev, loadAll, {once:true, passive:true}));
```

Отдельно: сторонние скрипты с cookie (карты, соцвиджеты) валят ещё и Best Practices
на мобиле — ленивая загрузка чинит оба показателя сразу.

## 4. Шрифты

- Только **самохостинг woff2** + сабсеты (кириллица + латиница), никаких запросов к
  Google Fonts.
- `font-display: swap`, `<link rel="preload">` на основной шрифт.
- **CSS шрифтов инлайнить в HTML** — иначе отдельный файл блокирует рендер.

## 5. CSS/JS и сервер

- Для лендингов: **CSS инлайном** в `<head>` (наши лендинги весят ~40 КБ HTML целиком),
  ассеты — внешними файлами.
- nginx (обязательный минимум):
```
gzip on;
gzip_types text/css application/javascript image/svg+xml application/json font/woff font/woff2;
listen 443 ssl http2;
location ~* \.(jpg|jpeg|png|webp|svg|woff2|mp4)$ {
  expires 30d;
  add_header Cache-Control "public, immutable";
}
```
- На css/js вешать cache-busting `?v=N` при каждом деплое, иначе люди увидят старую
  версию из кэша.
- Можно отдавать WebP автоматически вместо jpg/png через `map` + `try_files
  $uri$webp_suffix $uri` (так сделано на нашем сервере).

## 6. Кабинет и любые сайты с загрузкой файлов

Статику разогнать мало — если пользователи заливают картинки, они снова всё утяжелят.

**Сжимать на входе, в самом загрузчике.** В кабинете это `lib/img.ts` → `compressImage(buf, ext, maxDim)`:
ресайз под максимум (аватар 512, материалы 1600) + перекодирование (jpeg mozjpeg q82 /
png q80 palette / webp q82). **Формат сохраняем** — иначе ломаются URL в базе.
Любой новый маршрут загрузки обязан прогонять буфер через него.

Разовый пережим накопившегося: сначала **бэкап** (`tar czf`), перезапись только если
файл реально стал меньше. Наши прогоны: 148 МБ → 37 МБ (аватары по 2.6 МБ → 33 КБ),
обложки уроков 440 → 172 КБ.

## 7. «У людей далеко от сервера всё тормозит» (Владивосток, ДВ)

Реальный кейс: студенты рядом с Москвой не жаловались, а из Владивостока страница
ползла и видео не игралось. Порядок разбора:

1. **Замерить сам сервер.** `curl -w "%{time_total}"` с внешней точки. У нас вышло 0.2 с
   даже из Германии → сервер ни при чём, проблема в весе и расстоянии.
2. **Вес.** Каждый лишний мегабайт на длинном плече умножается: то, что в Москве
   незаметно, на ДВ превращается в десятки секунд. Сжатие картинок дало основной эффект.
3. **Расстояние.** Один сервер в Москве физически далеко. Настоящее лечение — **CDN с
   точками на Дальнем Востоке** (Gcore, Yandex Cloud CDN): статика раздаётся с ближней
   точки, сервер отдаёт только динамику.
4. **Видео** держать у видеохостинга (Kinescope и подобные) — у него своя сеть раздачи,
   свой сервер так не сможет.

⚠️ **Не путать «медленно» и «не работает».** Был случай: «бесконечная загрузка» уроков
выглядела как тормоза, а на деле Kinescope не пускал плеер, потому что домен кабинета
не был в списке разрешённых (`privacy_domains`). Симптом похож, лечение другое.
**Любое новое видео вайтлистить на все домены проекта сразу.**

## Чеклист перед сдачей сайта

- [ ] Замер PageSpeed **на мобиле** — производительность ≥90
- [ ] Все картинки WebP (по возможности AVIF через `<picture>`), ни одной тяжелее нужного размера; SVG через svgo
- [ ] У картинок заданы размеры (CLS = 0)
- [ ] Первый экран: постер-картинка с `fetchpriority="high"`, видео не блокирует
- [ ] Видео `preload="none"` + ленивый src; чужие плееры — фасадом по клику
- [ ] Своё видео на сайт — с `<source>` webm(AV1/VP9) + mp4(H.264); фон/герой автоплей: `muted playsinline` + WebP-постер
- [ ] HDR-видео (если есть) — только под `(dynamic-range: high)` + обязательный SDR-фоллбэк тон-маппингом
- [ ] Карты/виджеты/счётчики — лениво, не в `<head>`
- [ ] Шрифты самохостом woff2, CSS шрифтов инлайн
- [ ] nginx: gzip, http2, `immutable`-кэш на ассеты, cache-busting на css/js
- [ ] Проверено на медленной сети (в DevTools throttling «Slow 4G»)
