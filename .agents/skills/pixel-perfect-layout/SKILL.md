# Вёрстка «пиксель-в-пиксель» по референсу

Роль «верстальщик» и «ревьюер» ассистент играет сам, последовательно: сначала
верстает блок, потом КРИТИЧЕСКИ сверяет свой рендер с эталоном и выписывает
расхождения, потом чинит. Так до совпадения. Для большого объёма (много блоков
сразу) — можно вынести в мультиагентный workflow (верстальщик + ревьюер), но для
интерактивной работы блок-за-блоком быстрее делать в одном потоке.

## Что нужно от пользователя (уточнить, если не дал)
1. **Эталон** — скриншот макета ИЛИ ссылка/выделение в Figma (Figma точнее — см. ниже).
2. **Ширина экрана** эталона в px (напр. 1440) — верстаем и снимаем скриншот именно на ней.
3. **Шрифты и ассеты** — какие шрифты (файлы/Google Fonts), картинки/иконки/логотипы.
   Без нужного шрифта «пиксель-в-пиксель» по тексту недостижимо.
4. Куда верстаем: отдельный статический HTML (по умолчанию) или в существующий проект.

## Как достигаем точности (по убыванию точности)
- **Figma-макет подключён** (официальный Figma Dev Mode MCP — как подключить, см. раздел «Подключение Figma MCP» внизу): тянуть
  ТОЧНЫЕ значения — `get_design_context`, `get_variable_defs`, `get_metadata`,
  `get_screenshot`. Это даёт реальные px/цвета/шрифты/отступы → самый точный путь.
- **Только скриншот-эталон:** верстаем, рендерим, сверяем ГЛАЗАМИ + меряем свои
  значения через инспект/выполнение JS в превью (реальные computed px: размеры, отступы, шрифт,
  цвет). Правки формулируем в конкретных числах, не «чуть больше».

## Цикл работы (по одному блоку)
1. **Сверстать блок** — HTML/CSS. Единицы и сетка как в макете (обычно фикс-ширина
   контейнера под указанную ширину экрана; шрифты подключить).
2. **Запустить превью:** открыть файл во встроенном браузере-превью Claude Code (статике достаточно index.html; если превью-инструмента нет — локальный сервер `python3 -m http.server` и открыть localhost).
3. **Выставить ширину:** выставить окно превью ровно на ширину эталона (напр. 1440).
4. **Снять рендер:** скриншот превью.
5. **СВЕРКА с эталоном** (роль ревьюера — придираться):
   - наложить мысленно рендер на эталон, пройтись по чек-листу:
     размеры и положение блока, отступы (padding/margin/gap), размер/насыщенность/
     межстрочный шрифта, цвета (фон/текст/кнопки), выравнивание, радиусы, тени,
     размеры картинок, позиция и размер кнопок/иконок.
   - для спорных мест мерить фактические значения (getBoundingClientRect/getComputedStyle) и
     сравнивать с эталоном (или Figma-спеками).
   - выписать список расхождений КОНКРЕТНО: «заголовок 32px → надо 40px», «отступ
     секции сверху 48px → надо 64px», «кнопка #2a2a2a → надо #252525».
6. **Исправить** по списку. Вернуться к п.3–5. Повторять, пока расхождений нет.
7. **Показать пользователю пруф** — финальный скриншот + при желании рядом
   с эталоном. Затем следующий блок.

## Честные ограничения (сказать пользователю)
- «Пиксель-в-пиксель» реально при наличии тех же шрифтов и ассетов. Скриншот с
  другого монитора/зума/ОС может слегка отличаться сглаживанием — добиваем до
  визуального совпадения и точных числовых значений.
- Автоматический численный diff двух картинок (overlay pixelmatch) возможен
  отдельным node-скриптом (pixelmatch+pngjs), НО требует одинакового кадра/размера
  рендера и эталона. По умолчанию быстрее и надёжнее — визуальная сверка + inspect.
  Предлагать pixelmatch, только если пользователь хочет жёсткие числа diff.

## Мультиагентный режим (для объёма)
Если блоков много и хочется параллелить — Workflow: стадия «build» (агент верстает
блок по эталону) → стадия «review» (агент сверяет рендер с эталоном, возвращает
список правок) → цикл пока чисто. Требует явного согласия пользователя (это дороже).
Для обычной интерактивной работы — НЕ нужно, делаем в одном потоке.


## Подключение Figma MCP (для точных спеков из макета)
Нужен тариф Figma с Dev Mode (Professional+, Full seat) и десктопное приложение Figma.
1. В Figma desktop: правая панель → Dev Mode → «Set up MCP Server» → статус Enabled.
   Сервер живёт внутри приложения на `http://127.0.0.1:3845/mcp` (Figma должна быть запущена).
2. В терминале: `claude mcp add --transport http figma-desktop http://127.0.0.1:3845/mcp`
3. Перезапустить Claude Code. Появятся инструменты `get_design_context`, `get_metadata`,
   `get_screenshot`, `get_variable_defs` — выделяешь фрейм в Figma и просишь Claude забрать спеки.
Без Figma скилл тоже работает — по скриншотам-эталонам (точность чуть ниже).
