# Дизайн-комментарии (пины на макете)

Система «комментарии как в Figma» для **свёрстанного дизайна** сайта (многостраничного).
Клиент открывает ссылку, слева снизу — круглая кнопка. Клик по кнопке → показываются
все пины страницы + панель. Кнопка «＋ Оставить комментарий» → курсор-крестик → клик
по нужному месту дизайна ставит пронумерованный пин, пишешь текст. Клик мимо → всё
скрыто, остаётся только кнопка. В панели снизу — блок «Все страницы» со счётчиками:
сразу видно, где сколько правок.

**Чем отличается от прототип-комментов (wireframe-prototype):** тот — для серых
вайрфреймов на этапе структуры. Этот — для готового ДИЗАЙНА, когда согласуешь
внешний вид: пин привязан к точке на макете, чтобы обсуждать «вот тут отступ / вот
эту кнопку».

## Из чего состоит (файлы в `assets/`)
- `comments-widget.js` — весь фронт (кнопка, пины, панель, формы). Один файл, CSS
  инжектит сам, без зависимостей. Кладётся в папку с дизайном.
- `comments-server.js` — бэкенд хранения (чистый Node, без npm-пакетов). Хранит
  `comments.json` рядом с собой. Крутится на сервере под PM2.
- `install.py` — подключает виджет во все `.html` одной командой.

## Как поставить (5 шагов)

Пусть дизайн лежит на сервере по пути-URL `/mysite/` (папка `/var/www/mysite/`),
API будет по `/mysite/api/`.

**1. Подключить виджет во все страницы** (локально, в папке дизайна):
```
python3 install.py ./mysite /mysite
```
Это скопирует `comments-widget.js` в папку и вставит во все `.html` перед `</body>`:
```html
<script src="/mysite/comments-widget.js?v=1" data-api="/mysite/api" defer></script>
```
(`data-api` — адрес API этого дизайна. Если не указать — виджет возьмёт «папку виджета + /api».)

**2. Залить на сервер** папку дизайна (вместе с `comments-widget.js`) и `comments-server.js`.
Положи `comments-server.js` в отдельную папку, например `/opt/mysite-comments/`.

**3. Запустить бэкенд** под PM2 на свободном порту (проверь занятость: `ss -ltn | grep 3900`):
```
cd /opt/mysite-comments && PORT=3900 pm2 start comments-server.js --name mysite-comments && pm2 save
```

**4. Прокинуть API через nginx** — в server-блоке сайта, ВЫШЕ статик-локации `/mysite/`:
```nginx
location /mysite/api/ {
    proxy_pass http://127.0.0.1:3900/;
    proxy_set_header X-Real-IP $remote_addr;
}
```
Затем `nginx -t && systemctl reload nginx`.

**5. Проверить** (замени домен на свой):
```
curl -s https://ТВОЙ-ДОМЕН/mysite/api/comments        # -> []
```
Открой `https://ТВОЙ-ДОМЕН/mysite/` — слева снизу должна быть синяя кнопка. Поставь
тестовый комментарий, обнови страницу — он должен сохраниться. Готово, можно отдавать клиенту.

## Обновление виджета
Правишь `comments-widget.js` → заливаешь заново → **обязательно бампаешь версию**
(иначе браузер отдаст старый из кеша). Просто перезапусти установщик с новой версией:
```
python3 install.py ./mysite /mysite 2
```
(он поменяет `?v=1` на `?v=2` во всех html). Бэкенд при этом трогать не нужно.

## Настройка (необязательно)
- **Цвет кнопки/пинов под бренд:** добавь атрибуты в тег подключения:
  `data-accent="#2E6BFF" data-accent-dark="#1B4BC4"`.
- **Красивые имена страниц** в сводке: перед подключением виджета добавь на страницы
  ```html
  <script>window.DC_PAGE_LABELS = {'index.html':'Главная','pricing.html':'Тарифы'};</script>
  ```
  Без этого показывается имя файла.

## Как читать собранные комментарии
- Проще всего — открыть свой дизайн: кнопка → панель со списком, блок «Все страницы»
  показывает, где есть правки, клик переносит на страницу, клик по пину подсвечивает место.
- Отметить сделанное — «Решено» (перечёркивается, уходит из счётчика), можно «Вернуть».
- Всё сырьё лежит в `comments.json` рядом с `comments-server.js` (обычный JSON — можно
  открыть глазами или выгрузить).

## Как это устроено (кратко, для доработок)
- Координата пина: `x` = процент ширины документа, `y` = пиксели от верха документа.
  Пины лежат в слое высотой во всю страницу. Привязка к точке, не к элементу — при
  сильной смене вёрстки пины немного сместятся; для ревью дизайна на фиксированной
  ширине это не мешает.
- Один общий `comments.json` на весь дизайн; страницы различаются по имени файла
  (последний сегмент URL). Поэтому у каждой страницы дизайна должен быть свой файл
  (`index.html`, `pricing.html`, …).
- Всё оформление — CSS внутри `comments-widget.js`, префикс классов `dc-`, чтобы не
  конфликтовать со стилями самого дизайна.
