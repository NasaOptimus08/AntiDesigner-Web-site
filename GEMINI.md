# АРХИТЕКТУРНЫЙ МАНИФЕСТ И ПРАВИЛА СИСТЕМЫ: "ANTIDESIGNER CORE"

## 1. МИССИЯ И ГЛОБАЛЬНАЯ ЦЕЛЬ ПРОЕКТА
"AntiDesigner Core" — это закрытая автономная операционная система маркетинга, лидогенерации и продаж, созданная для веб-разработчика/студии, продающей разработку сайтов на «чистом коде» с ультравысокой скоростью загрузки (в противовес медленным конструкторам вроде WordPress/Tilda).

Архитектурная модель: **"Agent-in-the-Loop" (90/10)**.
- Агент берет на себя 90% рутинной работы: мониторинг трендов, написание омничеканального контента, технический и визуальный аудит сайтов конкурентов/лидов, квалификацию входящих заявок в Telegram-боте, ведение CRM и сбор аналитики.
- Человек выполняет роль Супервайзера (10%): принимает ключевые решения в один клик (утвердить тему, согласовать публикацию, отправить персонализированный питч, взять в работу горячего лида).

## 2. АРХИТЕКТУРА 8 ФУНКЦИОНАЛЬНЫХ МОДУЛЕЙ
Система представляет собой SPA-панель управления, разделенную на 8 взаимосвязанных блоков:

1. **Контент-фабрика (Omnichannel Engine):**
   - На вход подается 1 тема/инфоповод.
   - Система через специализированные промпты (Скиллы) генерирует пакет из 5 готовых материалов: лонгрид для VC.ru/Habr, GEO-статья для поискового SEO, пост для Telegram-канала, сценарий для Reels/Shorts и каркас PDF-лид-магнита.
   - Поддерживается предпросмотр в Markdown уже с идеальным форматированием для публикации и публикация в Telegram-канал по кнопке. и можно там же это все править и менять и после сохранять и публиковать

2. **CRM и Воронка Лидов:**
   - Канбан-доска статусов: `new` (новый) → `qualified` (квалифицирован) → `hot` (горячий) → `deal_closed` (сделка) → `archived`.
   - Автоматический сбор атрибуции: UTM-метки источника (какая конкретно статья или пост привели лида).
   - Фиксация бюджета (тарифы: 18к–25к, 25к–35к, 35к+) и выданных лид-магнитов.
   - Учет метрик эффективности контента (просмотры, лайки, конверсия в заявку, переходы по кнопкам и ссылкам).

3. **База знаний (Knowledge Context):**
   - Хранилище постоянного контекста для нейросети: описание целевой аудитории, боли клиентов, УТП «чистого кода», сетка тарифов, эталонные кейсы.
   - Данные подмешиваются в системные промпты при генерации контента и питчей.
   - Разделяется база на категории: для контента, для переписки с клиентами, для улучшения самого себя (модель сам себя с учетом базы знаний улучшает), CRM и выводы с учетом CRM

4. **Холодный аутрич (Outbound Audit & Pitch):**
   - Модуль аудита потенциальных клиентов. Принимает URL сайта компании.
   - Производит технический аудит производительности (Google PageSpeed Insights API).
   - Производит визуальный аудит дизайна первого экрана через Multimodal Vision (Gemini 1.5 Vision) по скриншоту страницы.
   - Генерирует готовый жесткий персонализированный питч для звонка или рассылки с демонстрацией слабых мест текущего сайта и предложением редизайна на чистом коде.

5. **Telegram-бот и Лид-магниты:**
   - Автономный клиентский бот на Webhook.
   - Выдает лид-магниты по кодовым словам из постов/статей.
   - Отвечает на базовые вопросы по тарифам и услугам на базе Базы Знаний.
   - Передает уведомление и контакт в админку при появлении горячего клиента.

6. **Радар трендов:**
   - Фоновый мониторинг IT-новостей и тематических источников через внешние поисковые API (Tavily / Perplexity).
   - Фильтрация инфошума и предложение 3–5 целевых инфоповодов. В один клик тема переносится в Контент-план.

7. **Интерактивный контент-план:**
   - Календарная сетка на месяц с распределением форматов и тем по дням недели с учетом болей аудитории с возможностью правок прям в влкдаке.

8. **Конструктор Скиллов (Prompt Engineering):**
   - Управление промптами без вмешательства в исходный код системы.
   - Редактирование системных инструкций для каждого формата (VC, Habr, TG, Reels, Pitch), настройка Tone of Voice и стоп-слов.
   - Вставка и заливка документо и файлов для скилов (python скрипты или Markdown и так далее)

9. **Контур самообучения (Feedback Loop / Agent Memory):**
   - Агент сопоставляет статистику вовлечения контента с реальными продажами из CRM.
   - Формирует выводы (например: «тема скорости сайтов дает в 2.5 раза больше лидов, чем тема типографики») и корректирует генерацию будущих контент-планов.

## 3. БЕЗКОМПРОМИССНЫЙ ТЕХНИЧЕСКИЙ СТЕК И ОГРАНИЧЕНИЯ

### Инфраструктурные ограничения (КРИТИЧНО):
- **Среда продакшена:** Классический виртуальный хостинг (Reg.ru / Beget, панель ISPmanager).
- **Лимиты сервера:** CPU 5.5%, диск 13 ГБ.
- **СТРОГО ЗАПРЕЩЕНО:** 
  - Никакого Docker и контейнеризации.
  - Никаких фоновых демонов Node.js / Python / Supervisor.
  - Никаких headless-браузеров (Puppeteer, Playwright, Selenium) на сервере хостинга (они мгновенно исчерпают 5.5% CPU).
  - Никаких тяжелых фреймворков (Laravel, Symfony, Django, LangChain, CrewAI) — они избыточны по памяти.
  - Никаких серверных инструментов сборки (npm, Webpack, Vite) на сервере.

### Технологический стек:
1. **Backend (Оркестратор):**
   - **PHP 8.3 (FastCGI)** в строгом режиме (`declare(strict_types=1);`).
   - PHP выполняет исключительно роль легковесного диспетчера: принимает REST-запросы, читает/пишет в SQLite, делает исходящие HTTPS cURL-запросы к внешним API и отдает JSON.
   - Потребление памяти одним скриптом не должно превышать 16–32 МБ.
   - Время выполнения веб-запроса — до 30 секунд.
2. **База данных:**
   - **SQLite 3** (один локальный файл `db/database.sqlite`).
   - Обязательная конфигурация при каждом подключении:
     `PRAGMA journal_mode = WAL;` (Write-Ahead Logging для устранения конфликтов чтения/записи)
     `PRAGMA busy_timeout = 5000;` (ожидание освобождения блокировки до 5 секунд)
     `PRAGMA foreign_keys = ON;`
   - Использование строго подготовленных выражений (PDO Prepared Statements) для защиты от SQL-инъекций.
   - Файл базы данных должен быть надежно изолирован от прямого скачивания по HTTP (через `.htaccess` или размещение выше web-root).
3. **Frontend (Панель управления):**
   - **HTML5, CSS3, чистый Vanilla JS (ES6+)**.
   - Архитектура: Одностраничное приложение (SPA).
   - Роутинг: Нативный хэш-роутер (`window.location.hash`), переключающий контейнеры вкладок без перезагрузки страниц.
   - Сетевой слой: нативный асинхронный `fetch()` с обработкой JSON.
4. **Внешний ИИ и Аналитические сервисы (Аутсорс всех тяжелых вычислений):**
   - **LLM & Multimodal Vision:** Google AI Studio (Gemini 1.5 Flash / Pro API) через REST cURL. Flash используется для быстрых классификаций и парсинга, Pro — для глубоких лонгридов и аудита дизайна.
   - **Технический аудит сайтов:** Google PageSpeed Insights REST API v5. Один HTTP-запрос возвращает готовую оценку производительности, метрики Core Web Vitals и скриншот первого экрана (base64) без запуска локального браузера.
   - **Мониторинг поиска:** Tavily API или Perplexity API для поиска трендов и новостей ниши.
   - **Мессенджер:** Telegram Bot API (вебхуки для приема лидов, отправка сообщений, авторизация 2FA).
5. **Фоновые процессы:**
   - Легкие PHP-скрипты в CLI-режиме, вызываемые встроенным планировщиком Cron хостинга (например, `cron_trends.php` раз в сутки, `cron_analytics.php` раз в 6 часов).
   - Защита от наложения процессов через механизм блокировок файлов (`flock`).

## 4. ИНЖЕНЕРНЫЕ ПРАВИЛА РАЗРАБОТКИ ДЛЯ АГЕНТА ANTIGRAVITY
1. **Автономность и самодостаточность модулей:** Каждый скрипт API в папке `api/` должен быть независимой конечной точкой, принимающей входные параметры, проверяющей авторизацию, взаимодействующей с SQLite/внешним API и отдающей валидный JSON с корректным HTTP-кодом.
2. **Безопасность путей:** Все файловые операции в PHP обязаны использовать абсолютные пути на базе `__DIR__` (например, `__DIR__ . '/../db/database.sqlite'`). Никаких относительных путей `./` или reliance на текущую рабочую директорию.
3. **Чистота и безошибочность:** Писать код без сторонних тяжелых библиотек. Обрабатывать все возможные исключения (`try-catch` вокруг сетевых запросов и базы данных) с логированием ошибок в JSON-ответ.
4. **Контракт интерфейса:** Не ломать структуру REST API и схемы базы данных. Если требуется модификация таблиц, оформлять ее в виде совместимых изменений.
